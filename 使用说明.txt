Planora 1.1.2 · 每日计划 · 独立桌面版（绿色免安装）
=====================================================

一、怎么启动
  1. 把整个 planora_1.1.2 文件夹解压到任意普通目录（桌面、D:\Planora 都行；不建议放
     C:\Program Files，也不要放在开发工程目录里）。
  2. 双击 Planora.exe。
  3. Planora 会打开「自己的窗口」（标题栏写着 Planora · 每日计划），看到时间轴就能用了。
  全程不会出现 CMD / PowerShell 黑窗，也不会再弹出浏览器标签页 —— 应用就在这个独立窗口里。
  · 再双击一次 Planora.exe 不会开第二个窗口，只会把已有的窗口叫到前台。

二、我的数据存在哪
  就在程序目录里：
      planora_1.1.2\data\planora.json
  这是纯文本，用记事本就能打开看。加、改、删计划都会立刻写回这个文件；
  关掉窗口再打开（甚至把这个文件夹整个拷到另一台电脑）都还是最新的数据。

  · 每次保存都是「先写临时文件 → 原子替换」，上一份自动留成 planora.json.bak。
  · 如果程序目录写不了（比如放在只读盘），会自动改存 %LOCALAPPDATA%\Planora\data\，
    页脚会写明当前实际用的是哪个路径。
  · 想自己指定位置：设环境变量 PLANORA_DATA_DIR。
  · 窗口引擎的缓存放在程序目录的 .webview2\ 里（只是浏览器内核的 profile，
    不是你的计划数据；删掉也不影响 data\planora.json）。

三、备份与搬家
  · 备份：页脚「导出备份」→ 下载 planora-<日期>.json，那就是全部计划。
  · 恢复 / 搬家：页脚「导入备份」→ 选那个 json，按 id 合并（同 id 覆盖，新 id 追加），
    不会清空现有数据。
  · 直接拷走 data\planora.json 完全等价 —— 它本来就是同一份东西。

四、从旧版本升上来
  1.0.0 的数据存在浏览器里（localStorage）。只要把新版解压到一个新文件夹、双击运行，
  且 5173 端口没被别的程序占用，第一次启动就会自动把老数据搬进 data\planora.json，
  页脚会显示「已把旧版浏览器里的 N 条计划搬进数据文件」。
  万一没搬成功：在旧版本页脚点「导出备份」，再在新版本点「导入备份」即可。
  1.1.x 之间升级：直接把旧文件夹里的 data\planora.json 拷进新文件夹即可，格式没变。

五、关掉它 / 它还在跑吗
  · 点窗口右上角的 × 关掉 Planora 窗口，程序就完全退出，后台不留任何进程
    （包括窗口引擎的子进程）。
  · 不会再有「关掉页面但服务还在后台跑」的情况：窗口开着服务才在，窗口关了服务一起停。

六、常见问题
  Q: 双击没反应？
  A: 先看同目录 data\planora.log 的最后几行。多数情况是杀毒软件拦了，把它加白名单。
  Q: 弹出「缺少 WebView2 运行时」？
  A: 这个窗口靠系统自带的 Microsoft Edge WebView2 渲染（Win10 / Win11 一般已内置）。
     万一没有，程序会先用系统浏览器打开保证你能用，并提示你去装
     「Microsoft Edge WebView2 Runtime」，装好后就是独立窗口了。
  Q: 提示端口被占用？
  A: 程序会自动改用 5180-5189 里的空闲端口，窗口里看到的还是同一个应用，无需处理。
  Q: 能不能直接双击 Planora.html？
  A: 可以，但那样没有本机服务，数据退回浏览器 localStorage（页脚会说明）。
     想要「数据存在程序目录」就双击 Planora.exe。

七、需要什么环境
  · Windows 10 / 11（用到系统自带的 .NET Framework 4.6.2+ 与 WebView2 运行时，默认都有）。
  · 不需要装 Node，不需要装浏览器，不需要联网。

八、日程很多时：批量添加
  一份课表几十上百条，一条条点太慢。数据就是纯文本的 data\planora.json，所以可以把
  「日程原文 + 这个文件」一起交给 AI Agent（Qoder / Claude / Cursor 之类都行），让它
  按规则整理好再写回文件 —— 程序不在乎这一条是谁写的，只在乎格式和字段过不过校验。

  三条最要紧的：
  1. 先完全退出 Planora（把窗口关掉）再动文件。页面把整份数据记在内存里，之后每次
     改动都是整份写回；程序还开着就改文件，刚写进去的内容会在下一次点击时被覆盖掉。
  2. 动手前复制一份 planora.json 当备份。文件被改坏时程序不会崩，而是把坏文件改名成
     planora.json.corrupt-<日期时间>，然后从空档继续跑 —— 看起来就像「计划全没了」。
  3. 外层文件里 keys["planora/plans/v1"] 的值是一个「字符串」，不是对象：里面那段计划
     JSON 是转义过的（引号写成 \"）。写成对象的话，读盘时这个键会被丢掉，打开就空了。

  另外两条容易忽略：校验没过的那条会被静默丢弃（不报错也不提示）；重复方式只有
  「每天」，所以周一/周三/周五的课要按每一个具体日期各写一条，不能用「每天」代替。

  完整字段规则、可直接复制给 Agent 的提示词模板、套信封的小脚本和写完的自检方法，
  在仓库里的 docs/bulk-schedule-import.md（https://github.com/WRM-FW/planora）。
  README.md 的「批量添加日程」一节是它的摘要。

  不想手改数据文件的话，还有更稳的一条路：让 Agent 产出一个「导入备份」格式的文件
  （plans 是真正的 JSON 数组，没有转义问题），再按第三节在页脚点「导入备份」——
  按 id 合并、由程序自己校验、不会清空现有数据。

九、文件夹里都有什么
  Planora.exe                          启动入口（自带窗口 + 本机数据服务，无控制台窗口）
  Planora.html                         应用本体（单文件，样式 / 字体 / 脚本全内联，也能单独双击使用）
  icon.ico                             程序图标
  Microsoft.Web.WebView2.Core.dll      窗口渲染引擎（WebView2）运行库，勿删
  Microsoft.Web.WebView2.WinForms.dll  窗口渲染引擎（WebView2）运行库，勿删
  WebView2Loader.dll                   窗口渲染引擎（WebView2）加载器，勿删
  data\                                运行后出现：planora.json 是数据（第一次改动时写出），planora.log 是日志
  docs\                                给 AI Agent 看的规则（第八节讲的批量添加日程）
  README.md                            设计与实现说明
